# Brainstorming

Use this guide when the request is exploratory, underspecified, or has several
reasonable solution paths.

1. Restate the outcome and constraints in plain language; inspect the existing
   project before proposing changes.
2. Ask only the highest-value clarification needed to choose between materially
   different approaches. Otherwise state a small, reversible assumption.
3. Compare a few practical options by user impact, complexity, risk, and fit
   with the current architecture. Recommend one and explain why briefly.
4. Break the chosen direction into small, verifiable steps. Do not start
   implementation until the intended behavior is clear.
5. Keep exploration focused on the user's goal; avoid expanding scope or
   treating speculative ideas as requirements.
